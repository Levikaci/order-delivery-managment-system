## [2.2.0]

Закрывает issue #9 (повторный аудит версии 2.1.0). Решения — [ADR-008](docs/decisions/ADR-008-deployment-idempotency-assignment-recovery.md).

### Безопасность
- Конфигурация разделена на Development и рабочее окружение: в `appsettings.json` нет пароля БД, учебные значения — в `appsettings.Development.json`.
- Вне Development сервер не стартует без строки подключения, со стандартным или коротким паролем PostgreSQL, с `Seed:Demo=true` и слабым `Seed:OperatorPassword`.
- `docker-compose.yml` — для локального запуска, порты только на `127.0.0.1`; новый `docker-compose.prod.yml` не публикует порт PostgreSQL и требует пароли из окружения (`.env.example`).
- Контейнер API запускается не от root.
- Сессии удалённых клиентов и курьеров сразу становятся недействительными.
- Сгенерированный пароль новой учётной записи — 12 случайных символов (было 6 цифр); заданный пароль проверяется на стойкость.
- Ограничение подбора пароля: 5 неудачных входов под одним логином с одного адреса — блокировка на 5 минут (`429 TOO_MANY_ATTEMPTS`). Ключ «логин + адрес» не позволяет постороннему заблокировать чужую учётную запись.
- Счётчики неудачных входов и попыток регистрации хранятся в PostgreSQL (таблица `rate_limits`, миграция 0007): общие для всех экземпляров API и не сбрасываются перезапуском.
- Адрес клиента за обратным прокси берётся из `X-Forwarded-For`, только если прокси указан в `ForwardedHeaders:KnownProxies` / `KnownNetworks`.
- Логин, заданный оператором при создании клиента или курьера, проверяется по правилам регистрации; ограничена длина телефона, имени, адреса, комментария и названия товара.

### Исправлено
- Повтор `POST /api/orders` с тем же `requestId`, но другими товарами, количеством, адресом или комментарием возвращает `409 IDEMPOTENCY_CONFLICT` вместо старого заказа (миграция 0005, `orders.request_hash`).
- Доставка, оставшаяся в `Created` после сбоя автоназначения или из-за отсутствия свободных курьеров, назначается автоматически фоновой службой.
- Сетевая ошибка при недоступной БД (`SocketException`) больше не превращала успешно созданный заказ в ответ `500 INTERNAL_ERROR` и считается временным сбоем (`STORAGE_ERROR`).
- Курьер с активной доставкой не назначается повторно, даже если его состояние ошибочно «Свободен» (уникальный индекс, миграция 0006).
- WPF-клиент повторяет создание заказа с тем же `requestId` при обрыве связи, не создавая дубль.
- При временной недоступности БД API отвечает `503 STORAGE_ERROR` с `Retry-After`; ошибки данных и SQL остаются `500` и не считаются временными.
- Одна доставка, назначение которой падает с ошибкой данных, больше не останавливает фоновое назначение остальных.
- Имя в сессии (`GET /api/auth/me`) обновляется после переименования клиента или курьера, а не остаётся прежним до следующего входа.
- Миграция 0006 больше не падает, если у курьера уже несколько активных доставок: лишние возвращаются в очередь назначения.
- Числовые значения статусов доставки и состояния курьера (например, `99`) возвращают `400 INVALID_REQUEST` вместо `500`.
- Символы `%` и `_` в строке поиска доставок ищутся как обычные символы.
- WPF: при изменении заказа сохраняется текущий адрес (не нужно вводить заново); адрес сервера без `http://` дополняется автоматически; доставки сортируются по времени создания; колонка «Адрес и клиент» шире.
- WPF-клиент при завершённой сессии (истёк срок, сменён пароль, удалена учётная запись) возвращает к окну входа вместо постоянного «Нет связи с сервером»; автообновление не накладывает запросы друг на друга.

### Добавлено
- Самостоятельная регистрация клиента: `POST /api/auth/register` и окно «Создать учётную запись клиента» в WPF; настройки `Security:AllowRegistration`, `Security:MaxRegistrationsPerHour`.
- `AssignmentRetryService`: периодическое назначение курьеров с экспоненциальной паузой при недоступной БД, безопасно для нескольких экземпляров API; настройки — секция `Assignment`.
- Проверка compose-файлов и сборки Docker-образа в CI.

### Изменено
- `GET /api/state` для клиента и курьера выбирает из БД только их доставки и связанные с ними записи клиентов, курьеров и адресов.
- Для локального запуска нужен `ASPNETCORE_ENVIRONMENT=Development` (уже задан в `run.sh`, `run.bat`, профиле Visual Studio и `docker-compose.yml`).

## [2.1.1]

### Удалено
- Утилита разового переноса данных из хранилища версий 1.x и её тесты: все установки работают на PostgreSQL, обновление версии выполняется миграциями при старте.

### Документация
- README и документы в `docs/` приведены в соответствие с PostgreSQL: убраны устаревшие сведения о прежнем хранилище, добавлен порядок обновления с резервной копией, исправлено описание `PATCH /api/deliveries/{id}/status` (причина неудачи передаётся в `comment`) и `confirm`.

## [2.1.0]

### Добавлено
- Сессии хранятся в PostgreSQL (в виде SHA-256 токена) и переживают перезапуск сервера (миграция 0004).
- `POST /api/auth/password` — смена пароля; остальные сессии пользователя завершаются.
- Боевой запуск без демо-аккаунтов: `Seed:Demo=false` + `Seed:OperatorPassword`.
- `POST /api/deliveries/{id}/retry` и кнопка «Повторить доставку» в WPF: неудачную доставку можно повторить, история сохраняется.

### Изменено
- Автоподбор курьера выбирает наименее загруженного за последние 24 часа (раньше — первого по имени).

## [2.0.0]

Закрывает issue #1 (замечания аудита).

### Изменено (несовместимо)
- Хранилище переведено на PostgreSQL (в версиях 1.x данные хранились в локальном файле). Для существующих установок была утилита разового переноса данных (удалена в 2.1.1).

### Исправлено
- Обновление схемы БД больше не удаляет данные: версионированные миграции в транзакциях.
- Неудачная доставка (`Failed`) больше не превращает заказ в `Cancelled`: добавлен статус заказа `DeliveryFailed`.
- Деньги хранятся в копейках (`BIGINT`), без двоичной арифметики `double`.
- Создание заказа устойчиво к сбоям назначения курьера; повторный запрос с тем же `requestId` не создаёт дубль.
- Изменение заказа без поля `comment` больше не стирает комментарий.

### Добавлено
- Журнал изменений заказа (состав, адрес, комментарий) с автором и временем.
- HTTP-тесты ролей, некорректного ввода, перезапуска и миграций.

### Удалено
- Неиспользуемые in-memory `OrderService`, `DeliveryService`, `IDeliveryService` и тесты, проверявшие только их.
