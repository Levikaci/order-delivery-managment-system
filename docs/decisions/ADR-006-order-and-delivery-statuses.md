# ADR-006: Статусы заказа и доставки

**Статус:** принято (v2.0.0, issue #1)

## Проблема

Неудачная доставка (`Failed`) превращалась в статус заказа `Cancelled`, поэтому «отмена» и «не смогли доставить» были неразличимы.

## Решение

Добавлен `OrderStatus.DeliveryFailed`. Статус заказа выводится из статуса доставки (`DeliveryRules.ToOrderStatus`):

| Доставка | Заказ |
|---|---|
| Created | Created |
| Assigned | Confirmed |
| Accepted | Preparing |
| InTransit | InDelivery |
| Delivered | Delivered |
| Failed | **DeliveryFailed** |
| Cancelled | Cancelled |

Допустимые переходы доставки не менялись; `Delivered`, `Failed`, `Cancelled` — финальные. `Failed` требует причину. Повторная доставка после `Failed` ТЗ не предусмотрена; с версии 2.1.0 оператор может повторить неудачную доставку того же заказа (`POST /api/deliveries/{id}/retry`): доставка возвращается в `Created`, курьер подбирается заново, предыдущая попытка остаётся в истории.

## Последствия

WPF показывает статус заказа в карточке и отличает неудачную доставку («Не удалась») от отмены.
