- добавлен `.gitignore` для проекта на .NET;
- настроено исключение каталогов `bin/` и `obj/`;
- настроено исключение локальных файлов среды разработки и временных файлов;
- добавлен `.editorconfig`;
- добавлены и оформлены документы проекта в каталоге `docs/`;
- добавлены правила работы с Git;
- добавлен журнал технических решений;
- добавлены документы проверки проекта;
- создан учебный файл для демонстрации конфликта;
- создан и разрешен учебный Git-конфликт;
- сформирована история изменений с несколькими логическими коммитами;
- создан контрольный тег `stage-2-git-config`.

Реальный исходный код приложения на данном этапе не разрабатывался, поэтому запуск `dotnet build` и `dotnet test` не выполнялся. Эти команды будут применяться на этапе реализации, когда в репозитории появится .NET-код.

## 3. История коммитов

Для проверки истории использовалась команда:

```bash
git log --oneline --graph --decorate --all
```

Фактически в истории присутствуют отдельные коммиты, посвященные:

- конфигурации репозитория;
- проектной документации;
- документам проверки;
- правилам работы с Git;
- журналу технических решений;
- добавлению учебного файла для конфликта;
- изменению учебного файла в варианте A;
- изменению учебного файла в варианте B;
- разрешению учебного конфликта;
- добавлению отчета по Этапу 2.

История содержит отдельные ветки для демонстрации конфликта и отображает их с помощью графа Git.

## 4. Учебный конфликт

Для выполнения требования по демонстрации конфликта использовался файл:

```text
docs/conflict-lab.txt
```

В конфликте участвовали две ветки:

```text
conflict-variant-a
conflict-variant-b
```

Обе ветки изменяли один и тот же учебный файл по-разному.

После объединения возник конфликт, который был разрешен вручную. Результат разрешения зафиксирован отдельным коммитом:

```text
Разрешение учебного конфликта
```

Факт наличия двух вариантов и последующего разрешения отображается в выводе:

```bash
git log --oneline --graph --decorate --all
```
