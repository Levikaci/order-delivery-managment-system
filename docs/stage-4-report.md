# Отчёт по этапу 4 — «Отладка отдельных модулей»

## 1. Цель работы

Проверить работу модулей системы управления доставкой заказов, выявить ошибки обработки входных данных, внести исправления и проверить ожидаемое поведение автоматизированными тестами.

## 2. Обнаруженные проблемы и исправления

### 2.1. Создание доставки с некорректными данными

**Проблема:** запрос на создание доставки с пустым адресом должен отклоняться.

**Исправление:** в `DeliveryService` проверяются запрос, идентификаторы доставки и клиента, а также адрес.

**Проверка:** интеграционный тест `CreateDelivery_WithEmptyAddress_ShouldReturnFalse`.

### 2.2. Создание заказа с некорректными данными

**Проблема:** `OrderService` не проверял `orderId` до обращения к сервису доставки.

**Исправление:** в начале `CreateOrderAsync` добавлена проверка `orderId`, `customerId` и `address`. При некорректных данных метод записывает предупреждение в лог и возвращает `false`.

**Проверка:** тест `CreateOrderAsync_WithEmptyOrderId_ShouldReturnFalse`. Также сохранён тест на пустой адрес заказа.

## 3. Средства разработки

- C# и .NET 9;
- Visual Studio;
- Git и GitHub;
- xUnit.

## 4. Проверка

Для проверки используется команда:

`dotnet test OrderDeliveryManagementSystem.sln`

Перед сдачей необходимо выполнить команду локально и убедиться, что все тесты проходят.

## 5. Организация работы

Изменения относятся к ветке `feature/stage-4-debugging`. Исправления и тесты сохраняются отдельными коммитами.

## 6. Вывод

Добавлена проверка входных данных в `OrderService` и тест, который проверяет отказ при пустом идентификаторе заказа. Вместе с проверками модуля доставки это позволяет отклонять некорректные запросы до выполнения основной операции.
