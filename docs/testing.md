# Тестовая стратегия

## До появления кода

Пока реализация отсутствует, автоматические тесты не создаются искусственно. На Этапе 1 фиксируются сценарии, которые должны быть проверены после реализации.

## Модульные тесты

Проверить:

1. создание заказа с корректными данными;
2. отказ при отсутствующем клиенте;
3. назначение свободного курьера;
4. отказ при занятом курьере;
5. допустимые переходы статусов;
6. запрет недопустимых переходов.

## Интеграционные тесты

### Успешное создание заказа

```text
ApiHost
 -> OrderModule
 -> CustomerModule
 -> DeliveryModule
 -> CourierModule
```

Ожидается создание заказа и доставки.

### Нет доступного курьера

Ожидается:

- заказ сохраняется в корректном состоянии;
- доставка остается `Created`;
- курьер не назначается;
- операция может быть повторена после появления доступного курьера.

### Завершение доставки

```text
Created -> Assigned -> Accepted -> InTransit -> Delivered
```

Ожидается корректная история статусов.

## Фактическое состояние

Реализовано 46 автоматических тестов (`dotnet test OrderDeliveryManagementSystem.sln`, результат: все проходят).

- `tests/OrderModule.Tests` — правила заказа (количества, редактирование, отмена клиентом, итог) и модульные правила доставки/курьера/клиента.
- `tests/Integration.Tests` — сценарии на реальной SQLite: создание заказа с автоназначением, нет свободного курьера, повторное назначение, занятый/офлайн/заблокированный курьер, полный путь до `Delivered`, `Failed` с причиной и без, недопустимые переходы, идемпотентность, отмена клиентом, подтверждение получения, адреса, редактирование, права ролей.
